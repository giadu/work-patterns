# Scoping Checklist

Before finalizing the task, check:

- is the goal stated in one or two sentences?
- is there a clear in-scope / out-of-scope boundary?
- are expected files listed when they are predictable?
- does the task say which existing code pattern to follow?
- are hidden assumptions written down explicitly?
- are acceptance criteria observable and testable?
- if this came from review comments, were those comments rewritten as implementation requirements?
- if multiple repos are involved, is the work split cleanly by repo?
- if a tracker-specific output is requested, is the title/body already final?
- if learning checkpoints were added, are they open-ended, evidence-based, and limited to a few concrete prompts?
- do the learning checkpoints avoid hiding hard requirements that should already be explicit?
- do the learning checkpoints require exact file references where relevant?
- do the learning checkpoints ask for a rejected alternative or tradeoff, not only the chosen path?
- do the learning checkpoints ask what bug or regression the planned tests are meant to catch?
